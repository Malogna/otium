# Automate the treasury, then add two partners

Otium can realistically add only two more bandwidth integrations in late 2026, and neither is large. The best addition is **Mysterium**. It runs on all three desktop OSes, pays in a liquid token, and is already embedded by Kryptex in a Windows mining app. The second is **one more per-device publisher SDK**, aimed at computers that Honeygain does not pay. **Decodo** (formerly Smartproxy) is the strongest new candidate: up to $0.20 per active user per month, Windows and macOS, and integrations accepted from about 1,000 daily users. Massive, from the earlier research, is the self-serve fallback. **Pawns** is the only per-GB SDK that now lists Linux, but it becomes viable only if IPRoyal confirms that idle-device traffic counts. Everything else surveyed fails a hard test: Infatica needs 50,000+ MAU and carries a Sophos PUA flag, most edge/CDN "DePIN" networks pay points or token emissions, and GagaNode, Grass, Nodepay and similar products are residential proxies under another name. Expect $0.10–0.30 per device per month from an SDK and a few dollars from Mysterium. The bigger gain is automating the money flow, and nearly all of it can be automated. Two hand-offs resist automation. First, PayPal has no documented API for topping up a business balance, so Payouts must run from a float that the operator refills by hand. Second, no EU-authorised exchange accepts XMR from EEA customers, so Monero is best paid out as Monero rather than converted. With credits that release on receipt, a coverage-ratio monitor, rule-based approval with a 72-hour auto-release queue, and in-app tax-form collection, the founder's routine shrinks to a weekly PayPal top-up, a daily digest, and the occasional exception.

## Mysterium and one per-device SDK are the only bandwidth additions worth building

Each candidate must pass three tests: it accepts a publisher that aggregates many users' devices, it runs inside a desktop app, and it pays in something Otium can turn into USD. Few pass all three. The 2026 survey found exactly two **new** publisher programs with current public SDK pages that list Windows and macOS, Decodo and Infatica. Both pay per active user per month, both are sales-led, and neither lists Linux ([Decodo](https://decodo.com/monetize); [infatica-sdk.io](https://infatica-sdk.io/)). Decodo's page contradicts itself between "up to $0.10" and "up to $0.20" per active user. Its annual tiers, though, work out to **$0.20 per DAU per month ($2,400/year at 1K DAU, $36,000 at 15K)**. It says apps with about 1K DAU "can also integrate". Its consent rules require explicit opt-in, compensation and easy opt-out, which match Otium's model as written ([Decodo](https://decodo.com/monetize)). Infatica pays "up to 60 cents per user" but requires **50,000+ monthly active users**. It also carries a Sophos PUA detection ("Infatica P2B in Non-Standard Location"), documented bundling inside K-Lite Codec Pack, and a 2021 controversy over undisclosed SDK placement ([infatica-sdk.io](https://infatica-sdk.io/); [Sophos](https://support.sophos.com/support/s/article/KBA-000043735?language=en_US); [Gridinsoft](https://blog.gridinsoft.com/k-lite-codec-pack-infatica-removal/)). For Otium, Infatica is out on both size and reputation.

Pawns (IPRoyal) has changed since the earlier research. Its SDK page now says the SDK is "available on Android, iOS, Windows, macOS, and Linux" subject to approval, and it pays a flat **$0.20 per GB** of shared traffic ([Pawns SDK](https://business.pawns.app/sdk/)). That makes it the only per-GB program covering all three desktop OSes. Two problems remain. First, the published SDK terms that the earlier research read treat traffic from idle devices without "active personal use" as invalid, and they list only Windows and macOS among desktop systems ([Pawns SDK Terms](https://business.pawns.app/sdk-terms/)). The new marketing page neither repeats nor withdraws that clause. Second, in September 2026 AhnLab documented malware that installed the **SOAX and IPRoyal SDK DLLs** on infected Windows PCs with an attacker's token. It also disabled Microsoft Defender, and AhnLab now detects these components as `Unwanted/Win.Proxyware` ([ASEC/AhnLab](https://asec.ahnlab.com/en/95516/)). The same report notes that Honeygain and Infatica had been abused in earlier waves. Honeygain denied any involvement. An Otium installer that ships the same IPRoyal DLL could share file hashes with flagged samples.

The rest of the candidate list falls away. Traffmonetizer, Repocket, PacketStream, Earn.fm, ProxyRack/Peer2Profit, SOAX, Oxylabs, Live Proxies, Rayobyte and Proxy-Cheap either sell proxies or run consumer "earn" apps; none has a developer-facing SDK program that could be found ([Proxyway 2026](https://proxyway.com/research/proxy-market-research-2026)). Among the edge, CDN and DePIN networks, only **AIOZ** pays a liquid token for serving content from a home PC without acting as a proxy exit. It has a headless CLI for Windows, macOS and Linux that can run as a service, a local `aioznode reward balance` query, and USD pairs on Coinbase and Kraken at about $5.5M of daily volume ([AIOZ CLI node](https://aioz.network/blog/aioz-dcdn-cli-node); [CoinGecko](https://www.coingecko.com/en/coins/aioz-network)). No dated per-node earnings exist, so AIOZ is a candidate to watch, not to build. Theta now pays EdgeCloud rewards in TFUEL, computed in USD, but the meaningful money goes to GPU nodes, and TFUEL traded around $0.013 ([Theta docs](https://docs.thetatoken.org/docs/theta-edgecloud-client-guide)). Titan advertises "$5–$30 monthly per device" and a partner SDK for apps that reward their own users. Nobody has confirmed that its TNT token trades, and it also leases IP addresses through a browser extension ([Titan Earn](https://www.titannet.io/earn)). Teneo and Dawn are pre-token points programs. Nodepay's token fell below $0.001 ([Zipmex](https://zipmex.com/blog/nodepay-airdrop/)). RIPE Atlas pays measurement credits, not money ([RIPE](https://www.ripe.net/analyse/internet-measurements/ripe-atlas/host-a-probe/)). GagaNode's status is disputed: an October 2026 blog describes it as live, while earlier sources reported Meson winding down. Either way it is a residential-proxy marketplace, so it belongs with the proxy SDKs.

| Candidate | Desktop OS | Pays | Entry bar | Per-user reporting | Verdict for Otium |
|---|---|---|---|---|---|
| **Mysterium (MystNodes partner token)** | Win, mac, Linux | MYST per GB; 20% settlement fee at 5 MYST | Partner token from MystNodes team | Per node identity via local REST API | **Build** (B2B-only traffic) |

| Massive SDK (earlier research) | Win (mac unclear) | $0.05–0.20/user/month, PayPal or wire | Self-serve | Dashboard | Fallback to Decodo |

| Infatica SDK | Win, mac | Up to $0.60/user/month | 50K+ MAU | None published | Skip (size, Sophos PUA) |
| AIOZ node | Win, mac, Linux | AIOZ token (liquid) | Open | Local CLI balance | Watch |
| Titan, Teneo, Dawn, Pipe | Mixed | Points / pre-TGE tokens | Open | — | Skip |

The economics argue against building every option. Published per-DAU figures converge on **$0.10–0.30 per user per month** in US and EU markets: Decodo up to $0.20, Honeygain an estimated $0.10–0.40, Bright $0.10–0.35 ([Proxyway, Dec 2025](https://proxyway.com/research/internet-sharing-sdks-app-monetization)). At 1,000 opted-in devices, an SDK therefore grosses roughly $100–300 a month. Mysterium's own illustrative range is **$2–8 per month for a casual laptop and $8–25 for an always-on node**, before its 20% settlement fee ([MystNodes blog](https://www.mystnodes.com/blog/how-much-can-you-earn-sharing-bandwidth); [Mysterium FAQ](https://docs.mysterium.network/faq)). Mysterium's 2026 change to a monthly points-to-MYST reward pool means the MYST amount per node is no longer fixed ([MystNodes on X](https://x.com/MystNodes_com)). Mysterium is the larger earner, but it also carries the larger liability. Mysterium advises node runners in the US, UK, Canada, Germany, Italy, Australia and India not to enable public traffic. Salad's 2025 bandwidth feature is the cautionary precedent: users reportedly received abuse notices such as 30,000 failed Netflix logins from their IP ([IBTimes](https://www.ibtimes.com/salads-bandwidth-sharing-causing-community-uproar-amid-abuse-legal-threats-3787696)). Content-serving nodes like AIOZ never route third-party requests out of a user's IP, which puts them in a lower risk class. That is why AIOZ stays on the watch list despite unknown yields.

The enforcement backdrop has not eased. After the January IPIDEA action, Google, the FBI, Lumen and IRS-CI moved against NetNut in July 2026. Its parent Alarum reported a material impact and cut about a third of its workforce ([Peakhour](https://www.peakhour.io/blog/ipidea-netnut-proxy-takedowns/)). No 2026 enforcement action was found against Decodo, Honeygain, Bright, IPRoyal as a company, Massive or Mysterium. Each extra SDK still adds antivirus surface to an installer that already carries XMRig and SRBMiner. So the cap is two additions, each behind its own consent screen.

None of the new programs publishes a per-device earnings API ([Pawns SDK](https://business.pawns.app/sdk/); [Decodo](https://decodo.com/monetize)). The crediting design follows from that. Per-DAU partners such as Honeygain, Decodo and Massive fit what Otium's `BandwidthService` already does: it credits a configured rate per sharing hour and pays only one computer per public IP. What changes is that rates and IP-deduplication rules must become per-partner, so a second household PC can earn from Decodo or Mysterium while Honeygain pays the first. Per-GB and per-node partners (Pawns, Mysterium) need actual measured earnings. For Mysterium those are available per node identity through its local Tequila API ([GitHub mysteriumnetwork/node](https://github.com/mysteriumnetwork/node)). For Pawns they would have to come from a local byte counter that IPRoyal has not documented.

## Revenue arrives in five forms, and only two need a human

The flow becomes manageable once each revenue source is treated as a pipe that ends in one of two funded pools: the Monero hot wallet or the PayPal balance. Only two joints in those pipes need a person. One is adding money to PayPal. The other is converting surplus XMR.

| Source | Arrives as | Automated path | Manual joint | Main risk |
|---|---|---|---|---|
| MoneroOcean (CPU) | XMR to operator subaddress | Directly into the hot wallet; pays Monero cash-outs | Converting XMR surplus (if any) | No EEA exchange; swap freezes |
| Kryptex Pool (Pearl, Quantus) | Auto-exchanged BTC/USDT/ETH/LTC | Pay out as BTC to an exchange deposit address, sell to EUR by API, SEPA to the business IBAN | PayPal "Add money" | USDT restricted in EEA; Kryptex docs inconsistent |
| Honeygain, Decodo, Massive (per-DAU SDKs) | Monthly fiat (method varies) | Ask for payment into PayPal where offered; otherwise bank | None if paid into PayPal | Unknown payout method/minimum for Decodo |
| Mysterium | MYST after 20% fee | Settle at 5 MYST, convert at an exchange | Conversion route to confirm | MYST volatility; route unverified |
| Pawns (if added) | Per-GB fiat | As per-DAU SDKs | — | Per-device attribution |

**Monero is best paid as Monero.** Kraken stopped XMR deposits and trading for EEA clients on 31 October 2024 ([Kraken](https://support.kraken.com/articles/support-for-monero-xmr-in-europe)). An October 2026 check of eight venues found Kraken blocking EEA users from its XMR pairs, KuCoin listing XMR without EU authorisation, and Coinbase, Bitstamp, Bitpanda, Bitvavo, OKX and Gate.io offering no XMR pairs. That check also notes that the EU AML Regulation will bar licensed providers from keeping accounts that allow anonymity-enhancing coins from **10 July 2027** ([CryptoTicker](https://cryptoticker.io/en/buy-monero-germany-delisting/)). The remaining exits are non-custodial swap services, and they are fragile. ChangeNOW reserves risk-based KYC; a competitor reports holds on privacy-coin pairs "especially above €2,000", and one unverified review describes a two-month freeze ([ChangeNOW policy](https://tostracker.app/document/changenowio-tos); [Baltex](https://baltex.io/blog/ecosystem/changenow-review-btc-to-xmr-swap-experience)). THORChain's native XMR support was announced in August 2026, yet THORWallet said in October that it was "currently being tested and audited" ([Decrypt](https://decrypt.co/376438/thorchain-3-20-unlocks-native-monero-and-zcash-swaps-with-bitcoin-ethereum-and-stablecoins); [Cointelegraph](https://cointelegraph.com/press-releases/thorwallet-integrates-monero-bringing-native-xmr-support-to-the-app)).

The clean answer is a natural hedge. MoneroOcean pays straight into a dedicated wallet subaddress, and Monero cash-outs are paid from that inflow. Only the net XMR position (inflow minus Monero cash-outs) carries price risk or needs an off-ramp. `monero-wallet-rpc` already provides what a float policy needs: `get_balance` with `unlocked_balance` and `blocks_to_unlock`, `get_transfers` filtered by direction, labelled subaddresses, and view-only wallets that produce unsigned transactions for a cold signer ([Monero wallet RPC](https://docs.getmonero.org/rpc-library/wallet-rpc/)). If Otium's users cash out mostly via PayPal, an XMR surplus will build up. The operator should then choose among holding it in cold storage, swapping it monthly with a documented trail, or nudging users toward Monero cash-outs with a small bonus. Each choice has tax and AML consequences for an accountant and counsel to weigh. Automating swaps through no-KYC services is the one automation this report advises against.

**Kryptex revenue should land as BTC, not USDT.** Kryptex Pool can auto-exchange Pearl and Quantus into BTC, USDT (BEP-20/TRC-20), ETH or LTC, with a USDT minimum of about 1 USDT plus network fee ([Kryptex Pearl pools](https://pool.kryptex.com/articles/pearl-mining-pools-en); [Kryptex news](https://www.kryptex.com/it/news/?page=6)). USDT is a poor intermediate asset for an EEA business. Kraken delisted USDT for EEA clients in Q1 2025 under MiCA and left deposits withdraw-only ([Cointelegraph](https://cointelegraph.com/news/kraken-usdt-delisting-europe-mica-stablecoin-compliance)). BTC paid to a Kraken deposit address can be sold to EUR by API and withdrawn by SEPA for **€1 (€2 minimum), or €0.90 by Instant SEPA (€3 minimum)** ([Kraken](https://support.kraken.com/gb/articles/360000423043)). One Kryptex comparison page claims the pool has no automatic BTC exchange, which contradicts its other pages. Kryptex also publishes no balance or withdrawal API, so its stats endpoints, which Otium's `KryptexCreditor` already reads, are the only automated window into it ([Kryptex vs Kryptex Pool](https://pool.kryptex.com/articles/kryptex-vs-kryptex-pool-en)). Whether threshold payouts to a fixed external address work for username-based accounts must be confirmed with Kryptex.

**PayPal is the bottleneck.** PayPal Payouts are funded only from the PayPal balance, which must cover payouts plus fees ([PayPal Payouts overview](https://developer.paypal.com/payouts/use-payouts/overview.md)). No source documents an API or scheduled auto top-up for that balance. Adding money from a linked bank is a manual "Add money" action. In Belgium it takes up to two business days, or about five minutes by Instant Top-Up for €25–1,000 ([PayPal BE](https://www.paypal.com/be/selfhelp/article/faq1348)). Whether Norway offers Instant Top-Up is unconfirmed. Two design moves follow. First, treat PayPal as a float sized at **two to four weeks of expected PayPal cash-outs**, so a weekly five-minute top-up is the founder's only routine money task. Second, prefer bandwidth partners that pay the publisher into PayPal, as Massive does, because their revenue refills the float with no human step ([Massive](https://www.joinmassive.com/getpaid)).

Currency is a hidden cost. Otium pays USD while a Norwegian business account likely holds NOK or EUR. Third-party sources put PayPal's conversion spread near 3%, which would exceed the roughly 2% Payouts fee itself ([ecomcalctools](https://ecomcalctools.com/blog/paypal-business-fees-2026/)). Holding and funding a USD balance should be the first question for PayPal.

## Credit pending, release on receipt, and watch one coverage number

Otium credits users every ten minutes at expected value, and money arrives days or weeks later. The gap is the operator's risk. Kryptex's own example shows auto-exchange moving monthly USD income by about **±10%** depending on the price path ([Kryptex](https://www.kryptex.com/en/articles/profitability-kryptex-app-pool-autoexchange-en)). Today's server treats every source alike, with a fixed 48-hour `HoldPeriod` before credits become available. That is too short for monthly-paid bandwidth partners and arguably too long for MoneroOcean.

A per-source policy fits better. Credits accrue as **pending at expected value minus a source-specific haircut**, tuned from observed drift, for example 5–15%. They become **available** when that source's corresponding receipt lands or after a source-specific maximum delay, and a daily reconciliation trues up the difference or absorbs it. For mining, "receipt" means the pool payout transaction seen in `get_transfers` or the Kryptex BTC deposit. For monthly-paid SDKs, waiting 30–45 days for the statement would hurt the user experience over cents. The better trade is to release after a short hold under the existing per-device daily cap, then correct the per-hour rate parameter at each monthly statement rather than claw back credits.

Behind this sits a reserve of roughly **10–20% of outstanding user liabilities** in EUR or USDC. Liabilities are matched by asset: stablecoin or fiat against the PayPal share, XMR only against the expected Monero share. These figures are design inferences, since no published case study of a mining-reward app's hedging policy was found.

One number captures solvency: the **coverage ratio**. It is hot wallet + PayPal + exchange + receivable pool and partner balances, divided by total user balances. Alert below 1.1 and pause automatic cash-outs below 1.0. Healthchecks.io's free plan monitors up to 20 cron jobs and alerts when one misses its expected run ([Healthchecks.io](https://canary.healthchecks.io/docs/healthchecks_cronitor_comparison/)). That covers the dead-man's switch for crediting, pool fetches, reconciliation, sweeps and the daily report. The business alerts below must be computed inside Otium's server and pushed by Telegram, ntfy or email.

| Alert | Starting threshold | Automatic action |
|---|---|---|
| Coverage ratio | < 1.1 warn; < 1.0 critical | Pause all automatic cash-outs at critical |
| PayPal float | < pending PayPal cash-outs + 7 days' average (warn); < pending (critical) | Queue PayPal cash-outs instead of letting them fail |
| Monero unlocked float | < 3 days' Monero cash-outs (warn); < 1 day (critical) | Slow the Monero queue |
| Monero float excess | > target + margin | Sweep excess to a cold, view-only-monitored address |
| Crediting stalled | No credit batch in 30 minutes | Healthchecks alert |
| Source drift | Credited vs received differs > 5% over 7 days, or no receipt past expected cadence | Raise that source's haircut; flag in digest |
| Payout failure | PayPal item FAILED/RETURNED/BLOCKED/UNCLAIMED; any wallet-rpc error | Refund to balance (already built) and list in digest |
| Velocity | Cash-outs/hour > 3× trailing p95; new accounts cashing out within 24 hours | Divert to hold queue |

The receipts ledger behind these alerts is also the tax ledger. Skatteetaten treats mined crypto as income at its **NOK market value when received**, and treats later price moves as separate gains or losses ([Skatteetaten](https://www.skatteetaten.no/person/skatt/hjelp-til-riktig-skatt/aksjer-og-verdipapirer/om/virtuell-valuta/mining/)). Every inbound receipt and every conversion therefore needs a timestamp, amount, source, transaction ID and NOK rate. Skatteetaten has announced stepped-up enforcement on undeclared crypto ([Skatteetaten press](https://www.skatteetaten.no/en/press/nyhetsrommet/skatteetaten-skjerper-innsatsen-mot-skjulte-kryptoverdier/)). Otium is arguably not mining for its own account at all; it sells users' compute and bandwidth and shares the revenue. Revenue classification, VAT on foreign B2B partner income, and the accounting for user balances are open questions for an accountant.

## Rules and a 72-hour auto-release replace most manual review

Otium's `CashoutService` holds a cash-out for review in six cases: the payout provider is not configured, the amount exceeds $50, the account is new and has never been paid, the destination is shared with another account, the $1,000 daily automatic budget is spent, or the user's yearly total passes $1,900. Each trigger has a sound purpose, but each turns into operator work. Because Otium's earnings come from measured hashrate and bandwidth, the real fraud vectors are multi-accounting, stats spoofing and referral abuse, not stolen cards. Rules that the server can evaluate cover most of that. The remaining edge cases can go into a queue that **auto-releases after 72 hours** unless the operator intervenes, which turns review into monitoring.

| Today's review trigger | Automated replacement | What still reaches the operator |
|---|---|---|
| New account | Account age plus earnings consistent with the device's measured hashrate or bandwidth, an email confirmation link per cash-out (Pawns confirms withdrawals by email and locks the method in flight; [Pawns](https://pawns.app/cashout/)), and an IP reputation check (proxycheck.io's free tier allows 1,000 queries/day; [proxycheck.io](https://proxycheck.io/pricing/)) | Failures go to the 72-hour queue |
| Amount > $50 | Per-user limits that rise with paid history (e.g. $50 → $150 → $500), plus the 72-hour queue above the tier | Only outliers versus device capability |
| Shared destination | Distinguish household (same IP, few accounts, distinct devices) from farms (shared device fingerprint across more than K accounts, datacenter/VPN IPs) | Farm patterns: hard hold, no auto-release |
| Daily budget | Make the cap dynamic: the lower of the fixed budget and the rail's float minus pending | Nothing; the queue simply waits for funding |
| US yearly total near $2,000 | In-app W-9 collection with TIN; release automatically once the form is on file; year-end 1099 export | Users who refuse to provide tax details |
| Provider not configured | Second rail (see below) | Nothing once a rail exists |

The tax trigger is the only one that genuinely needs data the server lacks, and the threshold has moved. Payments from 2026 trigger 1099 reporting above **$2,000** rather than $600 ([Avalara](https://www.avalara.com/blog/en/north-america/2025/07/one-big-beautiful-bill-act-1099-reporting-threshold.html)). The server's $1,900 hold is a sensible buffer below that. Collecting a W-9 inside the app removes the hold. Alternatively, a payout provider that collects W-9s and prepares 1099s can do it: Tremendous and Trolley both advertise this ([Tremendous](https://www.tremendous.com/pricing/); [Trolley](https://trolley.com/freelancer-payouts)). Sanctions screening is lighter than it sounds. PayPal screens its own recipients, Monero addresses cannot be screened meaningfully, and a country and IP geo-block of sanctioned jurisdictions is the minimal operator-side control. Whether Norwegian law requires more is a question for counsel.

### PayPal stays primary, and Tremendous is the only sensible second rail

At $2–50, per-payment fixed fees decide the rail. PayPal Payouts typically charges the sender **2% of each payout, capped**, and charges recipients nothing; per-currency caps and VAT vary by market ([PayPal fees](https://developer.paypal.com/payouts/fees.md)). Honeygain pays users through PayPal Payouts, which shows that PayPal approves bandwidth-reward businesses ([Honeygain](https://honeygain.com/blog/paypal-payouts-step-by-step-instructions)). Tremendous charges nothing for its platform or API and sends gift cards and prepaid Visa at face value. PayPal and Venmo through Tremendous cost 4% with a $0.25 minimum ([Tremendous](https://www.tremendous.com/pricing/)). The bank-transfer payout platforms are priced for larger B2B payments: Trolley charges $1 per ACH and $4 per SEPA payment ([erpresearch](https://erpresearch.com/erp-add-ons/global-payouts/trolley)), Hyperwallet recipients pay $3 to withdraw to a bank ([Wise](https://wise.com/us/blog/hyperwallet-review)), and Payoneer charges $4 per same-country transfer ([Tipalti](https://tipalti.com/resources/learn/payoneer-vs-hyperwallet/)). **Stripe Connect is out.** Its restricted-business list, updated 22 September 2026, prohibits "Cryptocurrency mining and staking" and schemes offering "high rewards for very little effort" ([Stripe](https://stripe.com/legal/restricted-businesses)).

| Rail | Fee on $2 | Fee on $5 | Fee on $20 | Fee on $50 | Tax forms |
|---|---|---|---|---|---|
| **PayPal Payouts (~2%)** | $0.04 | $0.10 | $0.40 | $1.00 | No |
| **Tremendous gift card / prepaid Visa** | $0 | $0 | $0 | $0 | W-9 + 1099 |
| Tremendous PayPal/Venmo (4%, $0.25 min) | $0.25 | $0.25 | $0.80 | $2.00 | W-9 + 1099 |
| Monero from hot wallet | Network fee only | Network fee only | Network fee only | Network fee only | No |
| USDC on Base via Coinbase Business | $0 (Coinbase claim) | $0 | $0 | $0 | No |
| Trolley SEPA | $4.00 | $4.00 | $4.00 | $4.00 | W-9/W-8 + 1099/1042-S |

Conversion spread of about 3% applies on top of PayPal's 2% wherever currencies differ (unverified third-party estimate). Coinbase's free-on-Base claim is the vendor's own ([Coinbase Business](https://www.coinbase.com/business/features-payouts)).

Tremendous fits as a second rail. Gift cards cost nothing and cover the countries where PayPal Payouts is unavailable, and Tremendous handles US tax forms. It also advertises fraud tooling, spend limits and account-takeover protection at no charge ([Tremendous](https://www.tremendous.com/pricing/)). The blocker is that no source shows whether it onboards a Norwegian company or accepts a mining-reward use case; only its sales team can answer that. A cheaper crypto option comes from Kryptex itself, which sends LTC to a user's PayPal crypto address instead of using fiat Payouts ([Kryptex](https://www.kryptex.com/articles/kryptex-paypal-en)). That fits the Kryptex-sourced BTC/LTC revenue, though PayPal supports crypto only in some countries. Comparable apps settle on PayPal plus gift cards plus crypto, with minimums of **$5 (Pawns) to $20 (Honeygain)** ([Pawns](https://pawns.app/cashout/); [Honeygain](https://honeygain.com/blog/paypal-payouts-step-by-step-instructions)). Otium's $2 crypto minimum is generous and economic only on Monero or gift cards.

## Build order for the server, the setup around it, and the open questions

The plan below puts money-flow safety before new revenue, because a bandwidth SDK earning $0.20 per device is worth less than one avoided week of manual review. The class names reference the existing server.

| Priority | Build in Otium's server | Why now |
|---|---|---|
| **P0-1** | **Receipts ledger**: ingest wallet-rpc `get_transfers` (per source subaddress), Kraken deposit/trade history, PayPal transaction history and partner statements; store amount, source, tx ID and USD/NOK rate per receipt | Basis for reconciliation, release-on-receipt and Norwegian tax records |
| **P0-2** | **Coverage and float monitor** with the alert table above, auto-pause per rail, a Healthchecks ping from every `BackgroundService`, and a daily Telegram/email digest (revenue by source, credits, cash-outs by rail, balances, coverage, flagged users) | Lets the founder monitor rather than operate |
| **P0-3** | **Risk engine in `CashoutService.ReviewReason`**: tiered limits by paid history, email confirmation link, IP reputation, device-fingerprint sharing, household-vs-farm logic for shared destinations, 72-hour auto-release queue, dynamic daily budget tied to float | Removes most manual review |
| **P0-4** | **In-app W-9 collection** for US users, auto-release of the $1,900 hold once a TIN is on file, year-end 1099 export | Removes the last routine review trigger |
| **P1-5** | **Per-source pending/available policy** replacing the global 48-hour `HoldPeriod`: haircut and release rule per source, daily true-up | Ties user liquidity to money actually received |
| **P1-6** | **Monero float manager**: target float, sweep excess to a cold view-only address, hard per-day outbound cap, separate subaddresses for MoneroOcean income and change | Natural hedge; limits hot-wallet loss |

Outside the server, the setup is mostly accounts and permissions. Get **PayPal Payouts approval** on a business account, holding a USD balance if possible, with a linked bank in the same name. Then put the weekly top-up in the calendar; it is the one recurring manual task. Open a **Kraken (or similar EEA-authorised) business account**. Give its API key trade and fiat-withdrawal rights to a whitelisted IBAN only, with no crypto-withdrawal permission, so a leaked key cannot drain funds. Switch **Kryptex auto-exchange to BTC**, paid to the Kraken deposit address. Point **MoneroOcean payouts** at a dedicated hot-wallet subaddress. Create a **cold Monero wallet** on an offline machine and register its view-only twin on the server. Set up **Healthchecks.io** (free tier) and a Telegram bot or ntfy topic. Choose a bookkeeping system that can import the receipts ledger with NOK rates. Finally, write down a policy for XMR surplus (hold, or swap monthly with a trail) before any surplus exists.

## Conclusion

This research changes where Otium's operating risk sits. On revenue, the bandwidth market has thinned into a few vendors that publish real terms, and each pays cents to a few dollars per device. Adding partners is therefore a portfolio decision about antivirus and abuse exposure more than a growth lever. On cash-outs, automation turns out to be bounded by banking rails and compliance, not by code. PayPal will not be topped up by API, and no EEA exchange will take Monero. The robust design keeps each currency in its own lane: Monero in, Monero out; mining revenue to BTC to EUR; partner fiat straight into PayPal where possible. A single coverage ratio then replaces case-by-case judgment.

The founder's job becomes a weekly five-minute top-up and a daily digest that lists only exceptions. That holds only if two non-technical answers come back favourably: PayPal's approval with USD funding, and counsel's view on whether holding user balances and paying in crypto requires a licence. Both should be asked before any of the P2 integrations are built, because a negative answer on either would reshape the payout side far more than any new bandwidth partner could add.
